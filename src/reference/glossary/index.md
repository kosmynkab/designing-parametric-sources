## About this glossary

As with any developing field, parametric source design has related terminology.
Some terms may be familiar; others have a specific meaning in this archive.
This glossary explains the terms used throughout the documentation and clarifies
how common terms are understood in the context of parametric design.

This list assumes an advanced type-design reader, so it does not define general
typographic concepts unless their use in parametric source design needs
clarification.

## Core terminology

### Design space
Complete range of possible manifestations of the typeface defined by the combined transformations from the source files. Think of all the possible combinations that the transformations can result in. The role of the designer is to cut away the unnecessary parts.

### Designspace file
Project file describing axes relationships, source locations and related data. In the parametric design it can be generated with a script.

### Default location
The origin from which the Δ transformations are calculated. In parametric design it is our regular font named wght400.ufo.

### Variable font
A built font file that combines the sourcefiles and the information held in the designspace file, blending and tunning instructions, to give users a powerful typographic tool.

## Parametric source framework

### Parametric design
An approach to designing a typeface that is a collection of parametric source .ufo files. Together with a designspace they allow to build a variable .ttf file. Through blending the parametric axes can be combined in a controlled way to produce user-facing axes (blended axes) that can be easily understood by end users.

The precise control of the transformations allows the font to have a wide range of styles. This in turn produces better typographic experience for the readers.
>see Parametric Design (incomplete)

### Parametric font
A variable font that is based on a parametric design approach.

### Parametric axis
A record of Δ transformations from the default to the sources. The combination produces a scale of the transformations ranging from the minimum through the default to the maximum. Parametric axes can be based on a measurement set between two points of a control character, or they can be arbitrary (for example GRAD axis) with pre-defined numbers

There can be two kinds - parent axes and child axes.

### Parent axis
Specific design transformations combined into a logical abbreviation. The transformation should be simple and clearly describe what it is responsible for. 

The parent axis can optionally be separated into child axes for better control. For example the Δy transparceny transformation is responsible for the vertical dimension of the character. It is referred to as YTRA – Y transparent. For the design this has to be separated – there are different transformations for Uppercase letters and lowercase x-height, ascender, descender, figures etc. 

Different projects can have different separation of the parent axes.
> see Parent Axes (complete draft)

### Child axis
An isolated transformation that is relevant to the project. For example XTUC – X-transparency of uppercase letters. That is a child axis of the XTRA parent axis group.
> see Child Axes (complete draft)

### Parametric source
An extreme design for a given parametric transformation. For example the XUCD715 is the max source for the uppercase diagonal shape sidebearing transformation. Only the affected glyphs should be different from the default.

### Parametric blending
A process of combining parametric axes into user-facing axes (often referred to as "blending").

## Workflow

### Key moment
A specific combination of user-facing axes points. 

### Tuning sources
A set of .ufo files that are generated by the controller that test the key moment design result of the designspace and calculate necessary delta transformations to achieve a matching result to the reference font in that same position. 

### Reference font
A set of source files and font files that allows for tuning the font at key moments. Reference font can exist before the parametric design process or it can be instantiated and modified to achieve the desired result in a specific location of the design space. 

### xTools4
Set of tools that provide extensive support in the process of designing parametric sources. They are necessary to operate on the system of sources, compute and produce tuning, and do other proofing and design changes in a surgical and systematic way.

More information can be found on the [xTools4 documentation website](https://gferreira.github.io/xTools4/).

### AVAR2

`avar` version 2 is an optional OpenType variable-font table that remaps axis
coordinates. Unlike the original version of `avar`, it can calculate a new
coordinate for one axis from the values of multiple axes.

This makes it possible to expose simple, user-facing controls while coordinating
multiple underlying parametric axes. In this archive, `avar2` is used to blend
parametric transformations into more intuitive user-facing axes.

## Axis register

### Parent parametric axes

### `XOPQ`
X opaque transformation. Weight of the horizontal contrast of the design. It includes that match the contrast across weight transformations.

### `YOPQ`
Y opaque transformation. Weight of the vertical contrast of the design. It includes that match the contrast across weight transformations.

### `XTRA`
X transparent. Transformation of horizontal transparency in a character (counterspace).

### `YTRA`
Transformation of the vertical transparency in a character. This can be height of the character, but also specific parts such as ascenders or descenders.

### `XTSP`
X transparent spacing. Horizontal transformation of sidebearings.

### `XSHA`
X serif horizontal. Horizontal transformation of horizontal serifs - serif length.

### `YSHA`
Y serif horizontal. Vertical transformation of horizontal serifs - serif thickness.

### `XSVA`
X serif vertical. Horizontal transformation of vertical serifs - serif thickness.

### `YSVA`
Y serif vertical. Vertical transformation of vertical serifs - serif length.

### `GRAD`
Adjustment to the darkness of the stroke. This transformation is arbitrary (no measurement is considered). It can help to adjust the result of the design in a specific setting i.e. dark/bright background optical weight matching.

### `YTOS`
Y transparent overshoots. Adjustment to the overshoot range.

### User-facing Axes
User-facing axes or blended axes are a result of the blending process and possible thanks to avar2 table. Multiple axes are combined (blended) to achieve a specific flow of the variable font through the designspace.
